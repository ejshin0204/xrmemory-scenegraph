# 시나리오

## PDF 사례: P4_절단_중_오류

| 시간 | 기록 | JSON |
|---|---|---|
| 0~12.43초 직전 | 공급 표시 켜짐 | states[0] |
| 10초 | A형 오류음 | event_01 |
| 10.5~12초 | 불꽃·절단 홈 불안정 관찰 보고 | observation_01, observation_02 |
| 12.1초 | HIGH로 판단했다고 보고 | interpretation |
| 12.4초 | 절단산소 차단 버튼 누름 | event_02 |
| 12.43초 | 공급 표시 꺼짐 | states[1] |

시나리오명 P4는 그대로 유지하고, 이 구간을 HTML의 DP5에 연결했습니다. 작업 상태 S4는 시나리오 문맥에 따른 예시 배치이며 화면에서 별도로 측정된 값이 아닙니다.

Decision UPDATE는 10초 오류음, 12.1초 판단 보고, 12.4초 조작, 12.43초 화면 변화의 네 기록입니다. 관측 구간은 12.1초 판단 기록의 근거 참조로 연결됩니다. 이전 기록에 미래 조작 결과를 미리 넣지 않습니다.

판단 보고를 참조하면 문서에는 selected_action_id가 보일 수 있지만, 당시 온라인 추론 입력으로는 이후 사건을 사용하면 안 됩니다. 이 예시는 사후 기록 연결용입니다.

## HTML 합성 사례: dp5-underreaction

| 시간 | 기준 위험도 | 예상 사용자 상태 | 대표 규칙 |
|---|---|---|---|
| 0초 | MID | Active Reasoning | R2 |
| 8초 | MID | Monitoring | R7 |
| 20초 | HIGH | Underreaction 가능성 | R5 |

이는 HTML에 작성된 예상값이며 실행·검증 결과가 아닙니다. 마지막 행동만으로 위험을 낮게 판단했다고 확정하지 않습니다. 과소평가와 위험 인지 후 미대응 두 가설을 함께 유지합니다.
